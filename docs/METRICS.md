# VANTRA Metrics Report

All numbers below are measured on this repository's synthetic data pipeline
(see NOTES.md). Generated by `vantra-api/scripts/evaluate.py`.

**OCR engine note (post-swap):** the text-recognition stage is now a pretrained
deep-learning model — EasyOCR (CRAFT detection + CRNN recognition) — replacing
the template-matching stand-in after its real-world failure (§6). The numbers
below are measured with the DL model. Confidence-aware thresholds were
recalibrated to its confidence distribution (correct reads p10 ≈ 0.59, wrong
reads mean ≈ 0.29).

## 1. OCR accuracy — clean vs stress (by condition)

| condition | n | exact match | exact % | usable (ed≤1) % | mean OCR conf | mean edit dist |
|---|---|---|---|---|---|---|
| clean | 60 | 59 | 98% | 100% | 0.81 | 0.0 |
| blur | 60 | 25 | 42% | 57% | 0.42 | 3.8 |
| angle | 60 | 31 | 52% | 70% | 0.66 | 2.4 |
| lowlight | 60 | 57 | 95% | 98% | 0.82 | 0.2 |
| occlusion | 60 | 50 | 83% | 92% | 0.78 | 0.6 |
| rain | 60 | 57 | 95% | 100% | 0.81 | 0.1 |

- **Clean validation set: 98% exact** (target >90% ✅)
- **Stress-test subset (pooled): 73% exact** — honest number; degraded reads carry low OCR confidence, which downstream fuzzy matching uses to widen thresholds instead of forcing wrong matches.

**Change vs the template-matching OCR** (before the DL swap): clean 100% → 98%
(one borderline read), blur 23% → 42%, angle 15% → 52%, occlusion 67% → 83%,
lowlight 98% → 95%, rain 100% → 95%. Stress conditions roughly doubled; the
clean dip is within noise and the usable (ed≤1) rate stayed at 100% for clean.

## 2. Trajectory stitching accuracy with injected missed cameras

| missed cameras | trials | full path reconstructed % | hops linked % |
|---|---|---|---|
| 0 | 27 | 100% | 100% |
| 1 | 26 | 100% | 100% |
| 2 | 30 | 80% | 89% |

**Full path vs hops linked.** "Hops linked" counts every consecutive ground-truth
camera pair that the matcher connected; "full path" requires *all* pairs in a trip
to be linked. A trip with 5 of 6 hops linked still contributes 5 to the first
number and 0 to the second.

**Where the 2-miss failures come from** (`scripts/diagnose_stitching.py`):

- **0 of the failures are wrong matches** — the matcher never linked two
  detections from different ground-truth trips at any miss level.
- Every residual 2-miss failure is a trip where the two skipped cameras were
  *adjacent* on the route, leaving consecutive detections **3 road-hops apart**.
  The matcher deliberately supports skipping exactly one camera; a 3-hop guess
  would be too weak to act on, so it refuses — an appropriate-caution failure,
  not an error.
- An earlier run of this benchmark understated stitching accuracy at all miss
  levels because it omitted Re-ID embeddings from the simulated detections,
  so unreadable-plate hops (which can only link via appearance) always failed.
  The benchmark now gives every detection the embedding a real deployment
  would always have; 0-miss and 1-miss full-path reconstruction is 100%.

## 4. Where the pipeline is weak (known)

- Motion blur remains the hardest synthetic condition (42% exact) but is far
  better than the template matcher's 23%; the OCR confidence correctly
  collapses on unreadable reads, and the appearance+route tiers carry those hops.
- Occlusion degrades gracefully (83% exact, near-miss errors).
- Low-light and rain are near-solved by the DL recognizer (95% each).

## 5. Scale stress test — 120 cameras, 1.2M detections

Separate dataset (`scripts/seed_scale.py`, database `vantra_scale`; the demo
dataset is untouched). Median of 3 runs, after the fixes below:

| query | latency |
|---|---|
| trajectory reconstruction (busiest plate, 74 detections + 4,700 candidates) | **1.5 s** |
| wildcard plate search | 2.6 ms |
| heatmap (count per camera, full table) | 38 ms |
| heatmap (24h window) | 23 ms |
| segment speeds (self-join) | 3.1 ms |
| tuning preview core (100 sessions) | 2.3 ms |
| live session create (busiest-hour scan) | 0.67 s |

Fixes made as a result (measured before → after):

- `build_matcher` now builds its camera graph from the database instead of the
  hardcoded 18-camera demo network — at scale it previously matched **zero**
  trajectories because grid cameras were never route-plausible (a real bug the
  stress test caught).
- `Matcher.stitch` buckets candidates by camera: only detections at
  route-reachable cameras are tested per hop. Stitch time on 4,700 candidates:
  2.3 s → 0.67 s.
- Appearance-candidate fetch restricts unreadable detections to cameras adjacent
  to the plate's own reads (route-plausible only).
- pg_trgm GIN index on `plate_raw` + partial index on unreadable detections:
  wildcard search 33 ms → 2.6 ms; full reconstruction 4.9 s → 1.5 s.

Honest numbers: reconstruction on the busiest plate in a 1.2M-row table is ~1.5 s
end-to-end — usable for an investigator view, not yet real-time streaming; the
production architecture (Kafka keyed by plate, per-key stateful stitching) is the
answer at larger scale, not query tuning.

## 6. Real-world OCR validation — fine-tuned model

**Full report:** [docs/REALWORLD_OCR.md](REALWORLD_OCR.md) — dataset composition,
train/val/test splits (by source, no leakage), complete iteration history, and the
error breakdown below.

**Held-out test (1,047 real photos, US/EU + Taiwan, never touched in training):**

| Model | Exact | Char accuracy |
|---|---|---|
| Template matcher (original stand-in) | 0.0% | 1.6% |
| Pretrained EasyOCR | 1.9% | 37.5% |
| **Fine-tuned EasyOCR (final, r3)** | **47.9%** | **78.3%** |

Fine-tuned on 7,318 real plates (2 public datasets) + augmentation = 29,272
training rows; CTC loss on the CRNN head, 4 hyperparameter runs, val plateau
~48%. Where it struggles: small crops <80px (18% exact) and oblique/squished
plates (24%); adequate-resolution plates read 56-63% exact / 84% char. Correct
reads mean conf 0.977 vs wrong 0.68 — the confidence signal the matcher uses
separates cleanly.

**Closing the gap to >90% (concrete, in REALWORLD_OCR.md):** 10-50x more labeled
real plates (CCPD-scale corpora), super-resolution for small crops, perspective
rectification for oblique plates. The ~48% is a data ceiling, not an architecture
limitation — the matcher consumes only (text, confidence) either way.

## 7. VLM-fallback pass (gemini-3.7-flash second-opinion)

Full report: [docs/REALWORLD_OCR.md](REALWORLD_OCR.md) — 9-configuration
model/prompt grid, per-image overlap analysis, threshold tuning, cost model.

**Held-out result (n=1,047): the VLM fallback does NOT improve accuracy.**

| Configuration | Exact |
|---|---|
| CRNN alone (fine-tuned) | **47.9%** |
| VLM alone (best: gemini-3.7-flash + plain) | 35.0% |
| Combined @ t=0.90 | 47.0% |
| Combined @ t=0.95 | 46.2% |

The VLM loses to the fine-tuned CRNN in every condition bucket, including the
small-crop and oblique-angle failure modes it was hypothesized to fix. Per-image
overlap: the VLM recovers only 30 images the CRNN misses while overwriting 165
correct high-confidence CRNN reads. Ships toggleable (off by default):
`VANTRA_VLM_FALLBACK=1`, `VANTRA_VLM_THRESHOLD=0.90`. Production framing: the
fast local CRNN remains the primary for both accuracy and cost on this data;
the VLM path exists for future conditions the CRNN cannot handle (non-Latin
scripts, multi-line plates) — unmeasurable with the current test set.

## 8. Accuracy-push pass (data expansion + SR) — negative result

Expanded training 2.9x (21,154 real crops: +12,590 Chinese, +518 Taiwan) and
added ESPCN-x2 super-resolution copies for small crops. Validation plateaued at
the same ~48%; **held-out accuracy dropped to 45.3%** (vs r3's 47.9%) — Chinese-
plate domain shift consumed model capacity without transferring to the US/EU/
Taiwan test distribution, and SR did not move the small-crop bucket (18.2%
unchanged). r3 remains the production model. Full analysis in
[REALWORLD_OCR.md](REALWORLD_OCR.md). The ~48% ceiling is now measured to be
architecture/distribution-bound, not data-volume-bound.

## 9. Indian-domain pass (2026-09-09/10) — leak-free split, new production model

The Indian train/val/test split was rebuilt **partitioned by unique plate
text** after the earlier image-level split was found to leak plates between
train and test (the earlier ~41% Indian figure is invalid and superseded).
Leak-free: 964 unique plates, zero overlap (test 152 plates / 312 images,
val 47 / 100, train 765 / 1,295).

**Leak-free Indian test (312 images, 152 unique plates, evaluated once):**

| Model | Exact | 95% CI | Char | Int'l exact |
|---|---|---|---|---|
| r3 (prior production) | 30.4% | [25.6, 35.8] | 76.7% | 47.9% |
| Indian-only fine-tune (best, inA2) | 53.2% | [47.7, 58.7] | 87.5% | 33.0% |
| inB1_sub (interim deploy) | 45.8% | [40.4, 51.4] | 84.8% | 47.2% |
| 4-model ensemble | 54.5% | — | 87.9% | 45.3% |
| **inC (final production)** | **50.3%** | **[44.8, 55.8]** | **87.1%** | **46.7%** |

**Small-sample caveat:** 152 unique plates → ~11pp confidence intervals; these
are ranges, not precise point estimates like the international 47.9% (n=1,047).

**Selection trail:** Indian-only models win Indian but forget international
(33.0%). inB1_sub (r3 + mixed 17k corpus) gained Indian without losing
international. A 4-model/5-strategy ensemble was tested and rejected (Indian
gain within noise; international regressed). Final round: inC (inB1_sub
continued on Indian-only data at low LR) — a strict improvement over inB1_sub
(+4.5pp Indian exact, +2.3pp char, international within noise) and the final
production model. Full history in [REALWORLD_OCR.md](REALWORLD_OCR.md). The
Indian training set (1,295 images / 765 plates) is the binding constraint.
